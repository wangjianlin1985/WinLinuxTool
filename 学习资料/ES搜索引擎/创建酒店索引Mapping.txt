中文解释：这是酒店索引库的 Mapping 配置，主要实现 中文分词、拼音搜索、综合字段搜索、酒店自动补全。我按模块给你复习一下。
1. 整体结构
hotel 索引库
├── settings             索引设置
│   └── analysis         分词器配置
│       ├── analyzer     自定义分词器
│       └── filter       拼音过滤器
└── mappings             字段映射
    └── properties       定义每个字段的类型和行为

可以简单记住：settings 管怎么分词，mappings 管数据怎么存储和搜索。

2. settings：分词和拼音配置，你定义了两个自定义分词器。
名称	分词方式	用途
text_anlyzer	ik_max_word + 拼音过滤器	中文全文搜索
completion_analyzer	keyword + 拼音过滤器	自动补全

text_anlyzer
"text_anlyzer": {
  "tokenizer": "ik_max_word",
  "filter": "py"
}
执行过程是：
1. ik_max_word：尽可能细地切分中文词语。
2. py：对分词结果进行拼音处理。

completion_analyzer
"completion_analyzer": {
  "tokenizer": "keyword",
  "filter": "py"
}
这里的 keyword 是把整个输入作为一个词元交给拼音过滤器，而不是先按中文词语拆开。它主要服务于后面的 completion 字段。


拼音过滤器 py
"py": {
  "type": "pinyin",
  "keep_full_pinyin": false,
  "keep_joined_full_pinyin": true,
  "keep_original": true,
  "limit_first_letter_length": 16,
  "remove_duplicated_term": true,
  "none_chinese_pinyin_tokenize": false
}
几个重要参数：
参数	作用
keep_full_pinyin: false	不单独保留每个汉字对应的独立全拼词元
keep_joined_full_pinyin: true	保留拼接起来的完整拼音
keep_original: true	保留原始中文
limit_first_letter_length: 16	限制首字母词元的长度
remove_duplicated_term: true	删除重复词元
none_chinese_pinyin_tokenize: false	不对非中文内容启用该选项对应的拼音分词处理
例如，酒店名称是“如家酒店”，拼音分析后可以支持类似 rujiajiudian 的搜索形式。实际生成哪些词元，取决于插件版本和具体配置。


3. mappings：酒店字段映射，你定义了 12 个字段，分别有不同用途。
字段	类型	用途
id	keyword	酒店唯一标识
name	text	酒店名称全文搜索
address	keyword	酒店地址，但不建立索引
price	integer	价格筛选、排序
score	integer	酒店评分筛选、排序
brand	keyword	品牌筛选
city	keyword	城市筛选
starName	keyword	星级筛选
business	keyword	商圈筛选
location	geo_point	地理位置、距离搜索
pic	keyword	图片地址，但不建立索引
all	text	多字段综合全文搜索
suggestion	completion	自动补全
注意：你这里实际是 13 个字段，因为 suggestion 也算一个字段。
为什么有些字段是 keyword，有些是 text？
- text：适合全文检索，例如“如家酒店”。
- keyword：适合精确匹配、聚合、排序，例如城市名称、品牌名称。
- integer：适合数值筛选，例如价格小于 300。
- geo_point：适合地理距离搜索。
- completion：专门用于搜索建议和自动补全。


4. copy_to: all 是什么？
你在三个字段里使用了它：
"name": {
  "type": "text",
  "copy_to": "all"
},
"brand": {
  "type": "keyword",
  "copy_to": "all"
},
"business": {
  "type": "keyword",
  "copy_to": "all"
}
它的作用是：把这些字段的值复制到 all 字段进行索引，但不修改原字段的值。
例如，一条酒店数据是：
{
  "name": "如家酒店",
  "brand": "如家",
  "business": "人民广场"
}
那么 all 字段会综合索引这三个字段的内容。查询时就可以针对 all 搜索，不必分别查询酒店名称、品牌和商圈。
不过，copy_to 并不是把这几个字段合并成一个可直接读取的 JSON 字段；它主要用于索引和搜索。


5. suggestion 才是自动补全的关键
"suggestion": {
  "type": "completion",
  "analyzer": "completion_analyzer"
}

这段定义了一个专门用于补全的数据结构。
例如，用户输入：
ruj

系统希望返回：
如家酒店

但有个容易忘记的地方：定义了 suggestion 字段，并不意味着酒店名称会自动进入这个字段。
插入酒店数据时，还需要提供 suggestion 的内容，在hotel-demo\src\main\java\cn\itcast\hotel\pojo\HotelDoc.java构造方法中提供的哈
{
  "name": "如家酒店",
  "brand": "如家",
  "business": "人民广场",
  "suggestion": [
    "如家酒店",
    "如家",
    "人民广场"
  ]
}

随后才能通过 Elasticsearch 的 completion suggester 执行补全查询。具体能否按拼音前缀匹配，要结合插件生成的词元和查询测试确认。


6. search_analyzer: ik_smart 是什么意思？
你给 name 和 all 都配置了：
"analyzer": "text_anlyzer",
"search_analyzer": "ik_smart"

二者作用不同：
- analyzer：写入文档时使用，决定字段内容如何分词。
- search_analyzer：查询时使用，决定用户输入如何分词。
这样设置通常是为了索引阶段尽量细分，查询阶段相对粗粒度分词，减少查询词被切得过碎的情况。、


最后记住这四点就行
1. settings：定义分词器和拼音过滤器。
2. mappings：定义字段类型及索引行为。
3. copy_to: all：把多个字段的值汇总到一个搜索字段。
4. suggestion: completion：为搜索建议和自动补全准备专用字段。
还有一个容易踩的坑：创建完 hotel 索引后，如果要修改已有字段的类型或分析器，通常不能直接修改现有 Mapping，需要新建索引并重新索引数据。
