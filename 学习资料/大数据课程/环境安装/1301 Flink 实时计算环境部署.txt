一、Flink 的运行架构 
Flink 主要有两个核心角色：
1. JobManager（作业管理器）
JobManager 是 Flink 的管理中心，主要负责：
- 接收用户提交的 Flink 作业
- 分析任务并生成执行计划
- 将任务分配给 TaskManager
- 管理任务运行状态
- 负责 Checkpoint 协调
- 任务失败后进行调度恢复
可以把 JobManager 理解成 Kubernetes 的控制管理角色，负责安排任务，但真正执行数据计算的是 TaskManager。

2. TaskManager（任务执行器）
TaskManager 是实际执行计算任务的进程，负责：
- 执行 Flink DataStream 等计算任务
- 接收上游数据
- 执行过滤、转换、聚合等操作
- 将数据发送给下游任务
- 提供 Task Slots（任务槽位）
3. Task Slots（任务槽位）
TaskManager 启动后可以配置多个 Slot。

例如：
JobManager
    |
    +---- TaskManager
              |
              +---- Slot 0
              +---- Slot 1
              +---- Slot 2
              +---- Slot 3
Slot 是 Flink 用来分配计算资源的逻辑单位。后面我们学习 DataStream 时会进一步理解 Slot、并行度以及算子之间的关系。

二、创建 Flink 数据目录
按照你的规划，所有 Flink 运行数据统一放在 /data/flink 下。执行：
mkdir -p /data/flink/log
mkdir -p /data/flink/checkpoints
mkdir -p /data/flink/savepoints

检查目录：ls -R /data/flink

目录用途：
目录			作用
/data/flink/log		Flink运行日志
/data/flink/checkpoints	自动Checkpoint存储目录
/data/flink/savepoints	手动保存作业状态目录

Checkpoint（检查点）
Flink 在运行过程中自动或按配置周期保存任务状态，用于故障恢复。
例如：
每60秒保存一次任务状态
当程序异常退出或节点故障时，可以根据之前保存的状态恢复计算。

Savepoint（保存点）
通常由用户主动触发，用于手动保存任务状态。
例如：
- 修改程序版本
- 升级 Flink 作业
- 停止任务后重新启动
- 调整任务并行度
Checkpoint 偏向自动容错，Savepoint 偏向主动运维与迁移。

三、设置 Flink 目录权限
如果你是使用 dsj_admin 用户安装和运行前面的 Hadoop、Kafka 等环境，那么这里也统一使用该用户。
执行：chown -R dsj_admin:dsj_admin /data/flink
检查权限：
ls -ld /data/flink
ls -l /data/flink

预期类似：
drwxr-xr-x dsj_admin dsj_admin /data/flink
这样 Flink 运行过程中就可以正常创建日志文件、Checkpoint 和 Savepoint。

四、配置 Flink 环境变量
你的 Flink 版本是 Flink 2.2.1，安装目录已经确定为：/usr/local/bigdata/flink
Flink 2.2.1 使用的是 config.yaml，不是旧版本教程中的 flink-conf.yaml。我们后面所有配置都以你机器上的 config.yaml 为准。

1. 编辑大数据环境变量文件
vi /etc/profile.d/bigdata.sh
追加Flink 环境变量：
# ==========================================
# Apache Flink 环境变量
# ==========================================
export FLINK_HOME=/usr/local/bigdata/flink
export FLINK_LOG_DIR=/data/flink/log
export PATH=$FLINK_HOME/bin:$PATH

2. 重新加载环境变量
source /etc/profile.d/bigdata.sh
检查：echo $FLINK_HOME
预期：/usr/local/bigdata/flink
检查 Flink 命令：which flink
预期类似：/usr/local/bigdata/flink/bin/flink

3. 查看 Flink 版本
flink --version
确认版本为：
Version: 2.2.1

五、配置 Flink 伪分布式运行环境
Flink 2.2.1 的配置文件：/usr/local/bigdata/flink/conf/config.yaml
先备份原始配置文件。
cd $FLINK_HOME/conf
cp config.yaml config.yaml.bak
查看当前配置：cat config.yaml

1. 修改 config.yaml
编辑：vi $FLINK_HOME/conf/config.yaml
将以下配置调整为我们这套单机伪分布式环境：

  # Flink log configuration
  log:
    dir: /data/flink/log
    level: INFO
    max: 10

# ------------------------------------------------------------------------------

  bind-host: 0.0.0.0
  rpc:
    address: master
    port: 6123
  memory:
    process:

# ------------------------------------------------------------------------------

  address: master
  bind-address: 0.0.0.0

七、配置 Flink Master 和 Worker

这里的 master 是你前面设置的 Linux 主机名，8081 是 Web UI 端口。

下面是创建Flink开机启动的步骤：
一、创建 Flink systemd 服务
使用 root 用户操作：vi /etc/systemd/system/flink.service
写入以下完整内容：
[Unit]
Description=Apache Flink Standalone Cluster
After=network.target
Wants=network.target

[Service]
Type=oneshot
RemainAfterExit=yes

User=dsj_admin
Group=dsj_admin

Environment=FLINK_HOME=/usr/local/bigdata/flink
Environment=FLINK_LOG_DIR=/data/flink/log
Environment=PATH=/usr/local/bigdata/flink/bin:/usr/local/bin:/usr/bin:/bin

WorkingDirectory=/usr/local/bigdata/flink

ExecStart=/usr/local/bigdata/flink/bin/start-cluster.sh
ExecStop=/usr/local/bigdata/flink/bin/stop-cluster.sh

TimeoutStartSec=180
TimeoutStopSec=180

[Install]
WantedBy=multi-user.target

这个服务使用 dsj_admin 用户启动 Flink，不会使用 root 运行 Flink 进程。

二、重新加载 systemd 配置
创建服务文件后执行：systemctl daemon-reload
三、设置 Flink 开机自启动
执行：systemctl enable flink
成功后，Flink 将会在 Linux 系统开机进入正常启动阶段时自动启动。

查看是否设置成功：systemctl is-enabled flink
预期输出：enabled


四、手动启动 Flink 服务
以后不用再手动执行 start-cluster.sh，可以直接使用 systemd。
启动：systemctl start flink
查看状态：systemctl status flink
正常情况下会显示：
Active: active (exited)

这里显示 active (exited) 对 Type=oneshot 服务是正常的，表示启动脚本执行完毕且服务被 systemd 标记为已启动；它不代表 Flink Java 进程退出了。还需要检查实际的 Flink 进程。

五、验证 Flink 是否启动成功
1. 查看 Java 进程
jps
检查是否有：
StandaloneSessionClusterEntrypoint
TaskManagerRunner

2. 查看 Web UI
浏览器打开：http://192.168.79.10:8081
如果 IP 不同，请使用你 master 当前实际 IP。

3. 查看端口
ss -lntp | grep 8081

六、Flink 服务管理命令（建议加入你的命令库）
命令			说明
systemctl start flink		启动Flink
systemctl stop flink		停止Flink
systemctl restart flink	重启Flink
systemctl status flink	查看Flink服务状态
systemctl enable flink	设置开机自启动
systemctl disable flink	取消开机自启动
systemctl is-enabled flink	查看是否已设置开机自启动
systemctl is-active flink	查看服务是否处于活动状态
journalctl -u flink -n 100	查看Flink服务启动日志
journalctl -u flink -f		实时查看服务日志


特别注意： Flink 的 start-cluster.sh 在 Standalone 模式下通常会通过 SSH 启动各节点进程。如果启动脚本需要 SSH，请确保 dsj_admin 已配置免密 SSH，特别是启动本机 master 时也能免密连接，否则开机时可能卡住或启动失败。
