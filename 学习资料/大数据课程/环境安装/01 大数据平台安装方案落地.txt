第一部分：统一软件版本规划
1.1 软件版本锁定
我建议采用以下版本作为第一版安装基线。这里优先考虑组件之间的 Java 兼容性、生态成熟度和后续学习价值，而不是一味追最新版本。
软件	计划版本	主要用途
OpenJDK	17 LTS	统一 Java 环境
Python	3.11.x	PySpark、PyFlink
Hadoop	3.5.0	HDFS、YARN、MapReduce
Hive	4.1.0	数据仓库、Hive SQL
Spark	4.0.1	批处理、SQL、Streaming
HBase	2.6.7	分布式 NoSQL 数据库
Kafka	4.0.x	消息队列、KRaft 集群
Flink	2.0.x	实时流式计算
ZooKeeper	3.9.x	HBase 协调服务
MySQL	8.0.x	Hive Metastore 元数据库

有几个版本选择需要特别说明：
- Hadoop 3.5.0 是第一个正式完整支持 JDK 17 的 Hadoop 版本。
  Apache Hadoop 3.5.0+1
- Hive 4.1.x 支持 JDK 17，Hive 4.0.1 则以 JDK 8 为要求，因此不选 4.0.1。
  apache/hive: Apache Hive · 
- Spark 4.0 系列使用 JDK 17，Python 3.9 及以上。
  AWS Big Data Blog
- HBase 2.6 系列支持 JDK 17，但要注意 Hadoop 版本匹配，建议选择带 Hadoop 3 的发行包。
- Flink 2.0 使用 JDK 17 作为推荐运行环境。
重要： 这是一套待集成验证的版本基线，不代表 Apache 官方对所有组件组合都提供了完整的联合认证。
尤其是 Spark/Hive 的 Hadoop 客户端依赖，以及 Flink/HBase Connector，需要在对应课程中做兼容性验证。

另外，Kafka 4.x 已经采用 KRaft 架构，不再使用 ZooKeeper 管理 Kafka 元数据；
但 HBase 仍然需要 ZooKeeper。这样我们可以分别学习两种不同的集群协调机制。

1.2 统一软件安装目录
两套方案都采用相同目录规范：
/usr/local/bigdata
│
├── jdk-17/                  # Java JDK
├── python3.11/              # Python（自行安装时使用）
│
├── hadoop/                  # Hadoop
├── hive/                    # Hive
├── spark/                   # Spark
├── hbase/                   # HBase
├── kafka/                   # Kafka
├── flink/                   # Flink
├── zookeeper/               # ZooKeeper
│
└── mysql/                   # MySQL（如采用独立安装）


数据目录单独规划，避免软件升级时误删数据：
/data/
│
├── hadoop/
│   ├── namenode/
│   └── datanode/
│
├── yarn/
├── hbase/
├── kafka/
├── zookeeper/
└── flink/


环境变量统一放在：
/etc/profile.d/bigdata.sh


这样所有用户都可以按照统一规范加载环境变量。
