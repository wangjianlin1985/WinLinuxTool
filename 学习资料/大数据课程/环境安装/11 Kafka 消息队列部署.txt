二、理解 Kafka 的工作原理
2.1 Kafka 是什么？
Kafka 是一个分布式消息队列系统，主要用于不同程序之间传递消息。
举个例子：
假设你有一个 Java 电商程序：
- 用户下单后，产生订单消息。
- Kafka 接收订单消息。
- 订单处理程序从 Kafka 获取订单消息。
- 库存程序也可以读取订单消息。
- 统计程序也可以读取订单消息。
这样，生产者不需要直接调用每一个消费者。

2.2 Kafka 核心组件
组件		作用
Broker		Kafka 消息服务器
Topic		消息主题，类似消息分类
Partition		Topic 的分区，用于并行处理和扩展
Producer		消息生产者，负责发送消息
Consumer	消息消费者，负责读取消息
Consumer Group	消费者组，实现协同消费
Offset		消息在分区中的偏移量
KRaft		管理 Kafka 集群元数据和控制器选举

2.3 Kafka 消息处理流程
Producer 消息生产者
Windows Java 程序 / Linux 程序
	↓
发送消息到 192.168.79.10:9092
Kafka Broker（master）
	Topic：order-topic
Partition 0		Partition 1
消息日志			消息日志	
	消息按照分区存储，分区内部有序
	↓
Consumer A		Consumer B		
订单处理			订单统计

这里有一个重要知识点：
同一个 Consumer Group 内的多个消费者会协同消费分区，一个分区同一时刻只会分配给组内一个消费者。
不同 Consumer Group 则可以各自读取同一份消息。

2.4 Kafka 与 ZooKeeper 的关系
以前 Kafka 依赖 ZooKeeper 管理集群元数据、Broker 注册和控制器选举。

现在 Kafka 4.x 使用 KRaft：
旧架构	新架构
Kafka + ZooKeeper	Kafka + KRaft
ZooKeeper 管理元数据	Kafka 内部控制器管理元数据
需要独立部署 ZooKeeper	不需要 ZooKeeper
ZooKeeper 负责控制器选举协调	KRaft 负责控制器选举

本课采用单机 Combined 模式：
- Broker：负责接收、存储和发送消息。
- Controller：负责集群元数据管理。
- 两种角色运行在同一个 Kafka 进程中。
注意：这是学习用单节点配置，不代表生产环境的高可用部署。

四、配置 Kafka KRaft 模式
4.1 修改 server.properties
切换到 dsj_admin：su - dsj_admin
进入配置目录：cd $KAFKA_HOME/config
备份原始配置：cp server.properties server.properties.bak
编辑：vi server.properties
将原有配置替换为下面这套单节点配置【】：

# ==========================================
# Kafka 4.4.0 KRaft 单机伪分布式配置
# ==========================================

# 1. Broker 和 Controller 角色
process.roles=broker,controller

# 2. 当前节点编号
node.id=1

# 3 KRaft 动态仲裁引导地址
controller.quorum.bootstrap.servers=master:9093

# 4. 监听地址
listeners=PLAINTEXT://master:9092,CONTROLLER://master:9093

# 5. 对外公布的客户端访问地址
advertised.listeners=PLAINTEXT://192.168.79.10:9092

# 6. Broker 通信协议
listener.security.protocol.map=CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT

# 7. Broker 之间使用的监听器
inter.broker.listener.name=PLAINTEXT

# 8. Controller 使用的监听器
controller.listener.names=CONTROLLER

# 9. 消息和元数据存储目录
log.dirs=/data/kafka/kraft-combined-logs

# 10. 内部 Topic 副本数
offsets.topic.replication.factor=1

transaction.state.log.replication.factor=1
transaction.state.log.min.isr=1

# 11. 单节点学习环境参数
group.initial.rebalance.delay.ms=0


几个重要配置解释：
配置		作用
process.roles	当前进程同时担任 Broker 和 Controller
node.id		当前 Kafka 节点编号
controller	.quorum.voters	KRaft 控制器成员
listeners		Kafka 实际监听的网络地址
advertised.listeners	告诉客户端应该连接哪个地址
log.dirs		消息数据和 KRaft 元数据存储位置
replication.factor	消息副本数量

这里最重要的是：
listeners=PLAINTEXT://master:9092,CONTROLLER://master:9093
advertised.listeners=PLAINTEXT://192.168.79.10:9092

为什么要配置两个地址？
- 9092：供 Windows、Linux 客户端连接 Kafka。
- 9093：供 KRaft Controller 内部通信。
- advertised.listeners：Kafka 返回给客户端的实际连接地址。
特别注意：不能将 advertised.listeners 配置成 localhost:9092，否则 Windows 客户端可能连接失败。

4.3 初始化 KRaft 存储目录
Kafka 第一次启动之前，必须初始化存储目录。
切换到 dsj_admin：su - dsj_admin
生成 Cluster ID：kafka-storage.sh random-uuid
得到类似：MkU3OEVBNTcwNTJENDM2Qk
注意：每次执行可能得到不同的 UUID。

初始化：
kafka-storage.sh format \
-t MkU3OEVBNTcwNTJENDM2Qk \
--standalone \
-c $KAFKA_HOME/config/server.properties

这里把示例 UUID 换成你自己生成的 UUID。
这个操作会在 Kafka 数据目录初始化 KRaft 元数据。
重要：只初始化一次，不要每次启动 Kafka 都执行 format。 已有数据时不要随意重新格式化，否则可能破坏现有集群元数据和消息数据。

5.1 先手动启动测试
先不要急着配置开机启动，先手动运行一次。

kafka-server-start.sh -daemon \

tail -f $KAFKA_HOME/logs/server.log

5.2 创建 Topic
Kafka 启动成功后，创建一个订单主题：
kafka-topics.sh \
--bootstrap-server master:9092 \
--create \
--topic order-topic \
--partitions 2 \
--replication-factor 1

参数说明：
参数		说明
--bootstrap-server	Kafka 连接地址
--create		创建 Topic
--topic		Topic 名称
--partitions	分区数量
--replication-factor	副本数量

这里创建了：
Topic：order-topic
Partition：2
Replication：1

为什么副本数量设置为 1？
因为目前只有一台 Broker，没有其他 Broker 可以存放副本。

5.3 查看 Topic
查看所有 Topic：kafka-topics.sh --bootstrap-server master:9092 --list

查看指定 Topic：

--describe \
--topic order-topic

预期能够看到：
Topic: order-topic
PartitionCount: 2
ReplicationFactor: 1

5.6 理解消费者组
再测试消费者组：
终端 A：
kafka-console-consumer.sh \
--bootstrap-server master:9092 \
--topic order-topic \
--group order-group

终端 B：
kafka-console-consumer.sh \
--bootstrap-server master:9092 \
--topic order-topic \
--group order-group

两个消费者属于同一个消费组。
因为有两个 Partition，Kafka 可以将两个分区分配给两个消费者。

查看消费者组：
kafka-consumer-groups.sh \
--bootstrap-server master:9092 \
--list

查看消费组详情：
kafka-consumer-groups.sh \
--bootstrap-server master:9092 \
--describe \
--group order-group

这里可以观察：
- 当前消费者组。
- 分区分配情况。
- 当前消费 Offset。
- 日志末尾 Offset。
- 消息积压量 Lag。
这也是以后排查 Kafka 消息堆积的重要手段。

7.4 编写生产者 KafkaProducerDemo.java
这个程序负责向 Linux Kafka 发送订单消息。

package com.example.kafka;

import org.apache.kafka.clients.producer.*;
import org.apache.kafka.common.serialization.StringSerializer;

import java.util.Properties;

public class KafkaProducerDemo {

    public static void main(String[] args) {

        // Kafka 连接配置
        Properties props = new Properties();

        // Linux Kafka 地址
        props.put(
            ProducerConfig.BOOTSTRAP_SERVERS_CONFIG,
            "192.168.79.10:9092"
        );

        // Key 和 Value 序列化方式
        props.put(
            ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG,
            StringSerializer.class.getName()
        );

        props.put(
            ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG,
            StringSerializer.class.getName()
        );

        // 创建生产者
        try (KafkaProducer<String, String> producer =
                 new KafkaProducer<>(props)) {

            // 模拟发送10条订单消息
            for (int i = 1; i <= 10; i++) {

                String orderId = "ORDER" + i;

                String message =
                    "orderId=" + orderId +
                    ",user=test,amount=" + (i * 99.9);

                ProducerRecord<String, String> record =
                    new ProducerRecord<>(
                        "order-topic",
                        orderId,
                        message
                    );

                // 发送消息并等待发送结果
                RecordMetadata metadata =
                    producer.send(record).get();

                System.out.println(
                    "发送成功：" + message +
                    " | Partition=" + metadata.partition() +
                    " | Offset=" + metadata.offset()
                );
            }

            producer.flush();

            System.out.println("全部订单消息发送完成！");
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}


这里有几个重点：
props.put(
    ProducerConfig.BOOTSTRAP_SERVERS_CONFIG,
    "192.168.79.10:9092"
);

这是连接 Linux Kafka 的地址。
new ProducerRecord<>(
    "order-topic",
    orderId,
    message
);


三个参数分别代表：
1. Topic 名称。
2. 消息 Key。
3. 消息 Value。
Kafka 会根据 Key 进行分区选择；在默认分区器下，相同 Key 通常进入同一个分区。

7.5 编写消费者 KafkaConsumerDemo.java
这个程序负责接收 Linux Kafka 中的订单消息。

package com.example.kafka;

import org.apache.kafka.clients.consumer.*;
import org.apache.kafka.common.serialization.StringDeserializer;

import java.time.Duration;
import java.util.Collections;
import java.util.Properties;

public class KafkaConsumerDemo {

    public static void main(String[] args) {

        Properties props = new Properties();

        // Linux Kafka 地址
        props.put(
            ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG,
            "192.168.79.10:9092"
        );

        // 消费者组
        props.put(
            ConsumerConfig.GROUP_ID_CONFIG,
            "windows-order-group"
        );

        // Key 反序列化
        props.put(
            ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG,
            StringDeserializer.class.getName()
        );

        // Value 反序列化
        props.put(
            ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG,
            StringDeserializer.class.getName()
        );

        // 新消费组从最早消息开始消费
        props.put(
            ConsumerConfig.AUTO_OFFSET_RESET_CONFIG,
            "earliest"
        );

        // 自动提交 Offset
        props.put(
            ConsumerConfig.ENABLE_AUTO_COMMIT_CONFIG,
            "true"
        );

        try (KafkaConsumer<String, String> consumer =
                 new KafkaConsumer<>(props)) {

            // 订阅 Topic
            consumer.subscribe(
                Collections.singletonList("order-topic")
            );

            System.out.println("消费者启动，等待订单消息...");

            while (true) {

                ConsumerRecords<String, String> records =
                    consumer.poll(Duration.ofMillis(1000));

                for (ConsumerRecord<String, String> record : records) {

                    System.out.println(
                        "收到消息：" + record.value()
                    );

                    System.out.println(
                        "Partition：" + record.partition()
                    );

                    System.out.println(
                        "Offset：" + record.offset()
                    );

                    System.out.println("--------------------------");
                }
            }

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}



消费者关键代码：
consumer.subscribe(
    Collections.singletonList("order-topic")
);
表示订阅订单主题。

consumer.poll(Duration.ofMillis(1000));
表示每次最多等待 1000 毫秒获取消息。

props.put(
    ConsumerConfig.AUTO_OFFSET_RESET_CONFIG,
    "earliest"
);
表示当消费组没有已提交的 Offset 时，从最早可读取的消息开始消费。

注意：earliest 不会让已经提交过 Offset 的消费组每次都从头读取。需要重新从头测试时，可以使用新的消费组名称，或者重置已有消费组 Offset。

九、特别注意：Kafka 4.4.x 的 KRaft 动态仲裁配置
这里补充一个 Kafka 4.4.x 的版本细节，避免你直接照抄旧版教程。
Kafka 4.4 官方已经提供动态 KRaft Quorum 配置方式。对于本课这种新建单节点环境，我建议采用动态仲裁方式，而不是旧式静态 controller.quorum.voters。

因此，前面第四节的配置文件中：
原来的：controller.quorum.voters=1@master:9093
应该替换为：controller.quorum.bootstrap.servers=master:9093
其他配置保持不变。

初始化命令继续使用：
kafka-storage.sh format \
-t 你的Cluster-ID \
--standalone \
-c $KAFKA_HOME/config/server.properties

这两项需要配套使用：
- controller.quorum.bootstrap.servers：动态仲裁模式。
- --standalone：初始化单节点动态仲裁。
这是 Kafka 4.4 官方文档推荐的配置方向。

如果你已经使用旧配置初始化了数据目录，不要直接修改配置后再次执行 format；应先确认是否有需要保留的数据，再决定是否重新初始化。
